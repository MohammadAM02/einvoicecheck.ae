# Hermes Hybrid Project Contract

For feature, brownfield, architectural, security, migration, and deployment work, use:

```text
Research → Specify → Analyze → Plan → explicit approval → Builder → Verify → Release → Handoff
```

## Required rules

- Research code, tests, configuration, and runtime assumptions before implementation.
- Record facts, contradictions, and unknowns in `specs/<task-id>/research.md`.
- Use `[NEEDS CLARIFICATION: ...]` instead of guessing requirements.
- Do not implement gated work before explicit user approval.
- Approval is bound to the hashes of `spec.md` and `plan.md`.
- Do not modify files outside the approved scope.
- Do not push, deploy, migrate production data, or rotate secrets without separate authorization.
- Inspect worker Git diffs independently.
- Verify on the merged tree, not only an isolated worker branch.
- Never claim success without fresh command output.

## Artifact locations

- Durable feature documents: `specs/<task-id>/`.
- Transient gate state: `.hermes/work/<task-id>/`.
- Gate scripts: `.hermes/gates/`.
- Project principles: `.hermes/constitution.md`.

## Lightweight routing

Trivial questions and comment-only edits may use a focused check. New behavior, public APIs, schemas, security boundaries, migrations, and deployment always use the full gate workflow.
